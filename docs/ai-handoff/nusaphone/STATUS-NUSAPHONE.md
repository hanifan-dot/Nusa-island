## Menunggu keputusan Owner

- **Kapasitas (GB virtual, usulan)**: Dasar 16 · s1 24 · s2 32 · s3 48 · s4 64 · s5 96 · Crown 17 128. Aplikasi inti 3 GB; lima game total 5,55 GB.

- Ocean Spin & ledger koin bermain: **terjawab di tahap 2** tanpa bidang baru — `eco.bal` = koin bermain (hanya naik lewat gameplay `credit()`/migrasi `ecoInit`), top-up = `ent.wallet.NYATA`; kode ponsel/Ocean Spin hanya membelanjakan `eco.bal` (uji statis menjaga: tepat 2 titik `.bal +=/=`, tidak ada rujukan NYATA/wallet/spendFrom). ## Keputusan desain Tahap 4 (Klippy / NusaChat / Dompet)
- **Klippy** = konten Server/Owner/NPC saja. Server: `klippyFeed` (kursor, maks 8/halaman, klien meminta 6, jeda baca 400 ms), `klippyLike` (kosmetik, opId), `klippyComments`/`klippyComment` (dimoderasi: kata kasar/tautan/nomor/email disamarkan, ≤80 huruf, jeda 8 dtk, ≤30/hari, tanpa komentar sama berturut-turut, nama dicadangkan diganti "Pemain"). Owner: `GET /api/klippy`, `POST /api/klippy/publish|withdraw|comments/remove`. **Kill switch** = saklar server `klippy` (bawaan MATI, di luar `gameFlags` publik, butuh `nusaPhone`). Tidak menyentuh ekonomi; tanpa UID/email/token di keluaran (uji + uji statis). Tidak ada data produksi yang dibuat: feed kosong sampai Owner menerbitkan.
- **NusaChat** = tampilan ponsel untuk chat multiplayer YANG SUDAH ADA (server tetap menyaring & membatasi laju). Pesan kini ditandai ruangnya (`sc`) saat diterima di `mp/client.js`; NusaChat hanya menampilkan ruang aktif (Rumahku / Area Muara / Kota selat) → tidak bocor antar-ruang; tamu Rumahku yang dikeluarkan (kode 4010) langsung kehilangan seluruh percakapan rumah itu & kolom kirim dikunci. Riwayat: 30 pesan terakhir di memori, tidak disimpan. **Blokir hanya di perangkat ini** (menyembunyikan di NusaChat); blokir sisi-server untuk chat area BELUM ada. **Rombongan kapal** tidak punya saluran chat terpisah di protokol saat ini (memakai chat area). **DM belum ada**: butuh kontrak server aman → tahap berikutnya (diputuskan Owner).
- **Dompet Nusa**: saldo dari server (`phoneState`: koin bermain `eco.bal`, koin top-up `wallet.NYATA` hanya DIBACA) + status pembayaran dari backend (`pay.available`; sampai adapter Payment Center sah aktif = "Pembayaran belum tersedia", tombol "Isi Koin" nonaktif). "Isi Koin" hanya memanggil `NW.shopUI.open("topup")` (Payment Center/Premium Shop lama). Regresi: berkas `shop/`, `firebase/functions`, aturan Firestore tidak diubah Ide 07 (diuji terhadap cabang dasar).
- Catatan uji: jam tiruan bridge kini berjalan mengikuti waktu nyata agar batas laju/jeda server teruji. `test_multiplayer.py` gagal di `#gwContinue` baik di cabang dasar maupun cabang ini (masalah lingkungan sebelum Ide 07, bukan regresi); `test_house.py` 83/0 lulus.

## Keputusan desain Tahap 5 (Toko NusaPhone di Kota + enam model)
- **Toko fisik**: bangunan "SEGERA HADIR" di Kota (`nusaphone`) tetap persis seperti semula bila server NusaPhone MATI atau flag klien `NUSA_PHONE=false` (papan "SEGERA HADIR", dialog lama, modul toko tidak diunduh). Bila server ON: papan "BUKA", etalase berisi ponsel kecil, titik pintu "Masuk toko" → `NW.phone.openStore()` memuat `phone/store.js` secara malas. Interior 2.5D (kanvas): lantai ubin + karpet, dinding dengan poster Lini A/B–C/D dan papan lampu "NUSAPHONE", dua rak aksesori, tiga meja etalase (dua ponsel per meja, enam model berbeda), konter kasir dengan ponsel dasar + NPC fiktif "Mbak Sari", lampu. Klik ponsel/NPC atau chip model untuk memilih.
- **Harga dari server**: tidak ada konstanta harga di `store.js`/`core.js` (uji statis). Harga koin/Rupiah, kapasitas (`mb`), status `buyable`/`reason`/`pending` ("menunggu Owner") semua dari `phoneState`.
- **Beli model koin (s1/s2)**: konfirmasi dulu → `phoneBuy` dengan `opId` unik yang disimpan di penyimpanan lokal (terikat akun, kedaluwarsa 15 menit) sampai server menjawab pasti. Jaringan gagal/jawaban hilang → tombol "Coba lagi" memakai `opId` yang SAMA (server mengembalikan hasil lama, tidak memotong dua kali). Muat ulang → pembelian tertunda dilanjutkan otomatis (hanya milik akun yang sama). Penolakan pasti dari server (saldo kurang, sudah dimiliki) → saldo tidak berubah, opId dihapus. Klik ganda → satu permintaan; dua perangkat/akun → satu pembelian per akun.
- **Premium (s3/s4/s5/Crown 17)**: tidak pernah dibeli di toko. Selama `pay.available !== true` (default sampai Tahap 6): tombol nonaktif "Pembayaran belum tersedia", "Isi Koin" nonaktif. Bila backend menyatakan tersedia: tombol "Beli di Payment Center"/"Isi Koin" hanya menutup toko lalu membuka `NW.shopUI.open("topup")` (Payment Center lama); kepemilikan hanya tercatat dari entitlement terverifikasi server.
- **Pakai & sinkron**: `phoneUse` (idempoten) lalu `NW.phone.sync` memperbarui daftar milik + casing ponsel. Sebelumnya `st.owned` klien tidak pernah disinkronkan dari server; kini `phoneState` diambil saat gerbang ON dan saat ponsel dibuka (maks 1×/20 dtk), sehingga model beli di perangkat lain ikut tampil.
- **Coba tampilan**: pratinjau klien saja (tanpa permintaan jaringan / perubahan data).
- Uji bukan bukti produksi: server = Worker asli + Firestore tiruan; antarmuka "pembayaran tersedia" diuji dengan mengubah jawaban `phoneState` di lapisan jaringan uji (keputusan nyata tetap di server dan ditolak 409 untuk premium).
